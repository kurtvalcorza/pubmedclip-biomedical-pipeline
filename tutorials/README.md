## Relation to the SigLIP rows

This notebook is the fleet's SigLIP `E2E` tutorial shape (`siglip2-vision-language-pipeline`, `siglip-v1-zero-shot-pipeline`) carried to a biomedical CLIP: the same six-module package, the same stages, baselines, metrics and adapter format, with three substitutions — CLIP's softmax scoring and cross-entropy adaptation in place of SigLIP's sigmoid, a pickle audit and one-time conversion in place of a hosted safetensors file, and a medical-image corpus with the dataset's own scan-disjoint roles in place of the bird photographs and their seeded split. It keeps the three drawn shapes and their inference contract as Section 5 and carries the adaptation contract around it: a real labelled image corpus fetched with archive and per-slice pins, a classification and retrieval protocol in the carried `metrics.py` (accuracy, macro F1, per-class recall / precision / F1 / AP, text-to-image mAP), two non-neural baselines, a bounded fine-tuning of the vision tower with the model's own scaled logits, a per-organ breakdown on two prompt sets, the shapes re-scored after adaptation, and an artifact that reloads. The per-grid `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's six modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative, replace the `resolve_weights_path` checkout-convenience line and remove internal relative package imports), Section 3 carries the 9-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12) and the pickle (asset spec §11):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh runtime lacks, at the pinned revision (never `main`); `verify_snapshot` re-hashes every entry; `PubMedClipPipeline.from_pretrained(weights_dir=WEIGHTS_DIR, progress=print)` audits the pinned `pytorch_model.bin` with `pickletools` (the fleet's four state-dict globals, audit digest pinned), unpickles it exactly once through `torch.load(weights_only=True)`, writes `model.safetensors` and refuses it unless its digest is the pinned one, then loads only that file (`local_files_only=True`, `trust_remote_code=False`, `use_safetensors=True`) and picks CUDA when it is visible. The `tf_model.h5` and `flax_model.msgpack` siblings are never fetched. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `torch.load`, `urllib`, `torch.optim` or the model's towers directly.
- **Data (DAT1–DAT9, ST6):** the default sample is 660 axial abdominal CT slices of eleven organs from MedMNIST+ OrganAMNIST at 224 px (CC BY 4.0), 60 per organ, pinned in the carried `samples.py` by MedMNIST split, index and slice SHA-256 and extracted from `organamnist_224.npz` (fetched from the authors' Zenodo record, verified by byte size and SHA-256, read with `numpy.load(allow_pickle=False)`); a cached or extracted slice is refused on any mismatch, and every record keeps its split and index. `build_sample_dataset(seed=SPLIT_SEED)` keeps the dataset's own roles (36 / 8 / 16 per organ → 396 / 88 / 176; the seed only orders the records) and `check_split_disjoint` asserts no slice (by decoded-pixel digest) is shared. The template's *External access* bullet names the archive, the byte count and the CC BY 4.0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` per split + `check_split_disjoint` + `source_overlap` + refusal probes (validation, with three digests) → `validate_inputs` + `zero_shot_classify` / `retrieve` / `embed_image` with sanity checks + `evaluation_report` on the drawn shapes (inference contract) → `majority_baseline` + `colour_neighbour_baseline` + `pipe.evaluate` on the frozen model with the per-organ breakdown and the raw-label prompt set (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `zero_shot_classify` + `evaluation_report` on the shapes again (inference) → `pipe.save_artifact` → `PubMedClipPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** classification scores are a softmax over the candidate prompts — relative, uncalibrated and prompt-dependent — and the classifier never abstains; accuracy, macro F1 and text-to-image mAP are computed from the model's own unnormalised `logits_per_image` (own numpy implementations) and none is a human judgement; no acceptance threshold ships. The shapes re-scored after adaptation carry a `sample-sanity` verdict that names the missing dispersion. The notebook states in the introduction, the prerequisites and the closing that nothing in it is clinical evidence.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the majority floor, the intensity nearest neighbour and the frozen model are scored on the same 176 test slices as the adapted model, on the three metrics and per organ; every metric is labelled as one run on one sample with no dispersion estimate, and the notebook says explicitly where the frozen model stands against the intensity neighbour, that the left / right organ pairs are invisible to a caption model, and that an 88-slice validation split moves accuracy in steps of about 1 %.
- **Split integrity (SPL1–SPL8):** roles are the dataset's own splits, which the authors drew by CT scan; validation (88 slices) selects the epoch on text-to-image mAP and the test split is used for nothing but the final evaluation; `source_overlap` prints which MedMNIST split feeds each role, and the notebook states that images from few patients, scans or sessions must be split by source. In BYOD mode the seeded split is stratified per label and image-disjoint, and the notebook says to group by patient or scan.
- **Ceilings (VAL6):** `TEXT_MAX_LENGTH` (77), `DEFAULT_PROMPT_TEMPLATE`, `MAX_IMAGE_SIDE` (4096), the record bounds (8..20,000), the class bounds (2..100), the 64-character label ceiling and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (no `extractall`) into the runtime and its `labels.csv` records flow through the same validation, image-disjoint split, baselines, fine-tuning, evaluation, export and reload cells. The expected schema and the privacy guidance — including that identifiable patient data must not be uploaded to a hosted runtime — are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/pubmedclip_biomedical_train.csv` in the same shape.
- Licence: the weights are MIT and the notebook, README and card say so; the slices are CC BY 4.0 and are not redistributed — the export records the corpus name, release, URL, archive byte count, archive digest and licence under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
